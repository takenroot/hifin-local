# 设计原则（长期基准）

> 提取自 2026-10-04 design-review（审查版本 `24422a4`）§5「做得好的地方」。
> 原报告的 32 项问题清单绝大部分已修复（design-fix 批次 `036b6d4`~`9c438db`、
> T1~T8、UI 批次 `96878d7`），问题目录归档于 [archive/design-review.md](./archive/design-review.md)；
> 本节是**与时间无关的"什么是好"的基准**，新代码应当达到这条线。

1. **令牌注释按暗色边框那段的格式立标准**：公布实测比值、说明紧约束在哪、保留色相的理由。推导过程写进注释，后来者不用重算。
2. **`Select.tsx` 是所有基础组件的参考实现**：完整 ARIA 语义、全键盘支持、`useId`、焦点归还，外加解释"为什么手写"的头部注释。
3. **组件拆分要有据可查**：像 `SegmentedControl` 那样写明触发拆分的具体故障。带理由的拆分才是成熟的设计系统。
4. **注释解释决策，不解释语法**：`useApi` 的 SWR 契约（loading="没东西可显示"、后台失败保留陈旧数据、暴露测试接缝）是模板。
5. **主题切换零缺陷**：首屏前内联引导 + `matchMedia` 实时订阅，"跟随系统"分支必须正确回落。
6. **插画用 `currentColor` 手绘**：免费换肤、无硬编码色、`aria-hidden`、显式尺寸。
7. **危险操作的标准线**：平实语言讲清毁掉什么/保留什么，导出紧挨着，键入确认字样才激活按钮。
8. **占位要诚实**："仅 UI 兼容"讲明白，不留静默死选项（本轮已清理语言死选项）。
9. **口径对账注记**：饼图/分布百分比肉眼可核对，"另有 ¥X 未计入"这类小字消灭"数字不对"的反馈。
10. **可比较的数字一律 `tabular-nums`**：余额列是扫读的，不是抖动的。
11. **加载文案带正确省略号**：`保存中…`，纯文字不闪 spinner。
12. **零 `will-change` 过度声明**。
13. **类型纪律**：`strict` + `noUnusedLocals/Parameters` 下 `tsc --noEmit` 干净通过是底线。

## 项目专属硬约定（补充于设计审查之后）

- 金额语义（2026-10-06 主题还原，对齐复刻源 §11.2）：收入=绿 #10b981 / 支出=红 #ef4444，
  **只给钱的去向**。此前「收入红/支出绿」是 REST 迁移批次的曲解，已全站还原
- 好坏语义与金额语义同轴：好事=绿、坏事=红（涨跌/净资产/余额/年收益一致，
  好事→text-income、坏事→text-expense；注释里写语义不写「红/绿」字面，令牌换值不再翻注释）
- 品牌主色：炭黑 #26262b（原版登录页/AI 设置页实测），dark 模式反转 #d4d4d8；
  按钮/链接/强调位一律炭黑，彩色只留给钱（income/expense）
- 色块卡上的大金额用 deep 变体（income.deep #047857 / expense.deep #dc2626）——soft 底上原色对比度不足
- 图表数据色（recharts 吃 JS 字面量）：lib/chartColors.js 是令牌的 JS 镜像——
  资产/趋势线=炭黑，收支数据=绿/红；改主题色必须同步改它
- 用户色板（分类/标签/目标可选颜色）不受主题约束，是用户数据
- 禁止 hover 阴影（design-consistency 回归闸断言 = 0），层次靠色块/边框
- 动效：`--dur-*`/`--ease-*` 令牌；入场一律 ease-out，禁用 ease-in；`animate-spin` 不受 reduced-motion 影响（进度信号）
- 暗色模式与亮色同标准（边框 3:1 推导注释是格式模板）
